<objective>
Grow `DatabaseOptions` and `quiver_database_options_t` to carry an explicit UI config
directory and a locale, thread both through the one C++ constructor and the one lazy
loader that consume them, and freeze the C header that Wave 2's four FFI plans all read.

**User story** (MVP mode; every clause taken verbatim from the ROADMAP Phase 2 `**Goal:**`
line — nothing invented, see the planner note at the end of this plan):
**As a** consumer in any binding, **I want to** open a database pointing at a UI config
directory anywhere on disk, in a locale of my choosing, **so that** claw — whose config
lives at `<installRoot>/database/ui` and whose read sandbox cannot reach `<db_dir>/ui/` —
is unblocked.

Purpose: this plan is the header freeze. D-19 makes everything downstream parallel, but
only once every C symbol the four binding plans reference exists and is built. It also
carries the SAFE-01 accessors, because they live in the same two headers and a second
plan editing them would serialize Wave 2 for no reason.
Output: a 24-byte options struct, three size accessors, one new boolean getter, and two
new test suites that prove the config and the locale actually crossed the boundary.
</objective>
