**As a** Julia or Dart consumer,
**I want to** the same four-struct load-time refusal the Python and JS bindings give me,
**so that** the safety guarantee does not depend on which host language I happened to pick.
</user_story>

<objective>
Expand the tracer's mechanism to the remaining two bindings: Julia and Dart each gain the fourth
struct in their load-time gate and a test that fails when the gate is unwired.

`Struct Sizes | 23 pass` with `_assert_struct_sizes()` deleted from `__init__`, and
`bindings/julia/test/test_struct_sizes.jl:18` is a literal `@test true` whose comment claims the
module load proves the gate ran. Dart was not separately measured but has the same shape: its tests
drive `checkStructSize`, not the wired `bindings` getter.

Output: two four-wide gates, two ordered-record assertions, two mutation-verified suites, and the
generator discipline honoured exactly — Julia regenerated, Dart hand-edited.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Julia/Dart runtime ↔ native library | Both bindings hold struct layouts independently: Julia via a generated `mutable struct`, Dart via a hand-edited `ffi.Struct`. Either can drift from the native header with no compile error at the FFI boundary. |
| generated artifact ↔ hand-written safety code | Julia's `c_api.jl` is regenerated; a safety check written there is silently deleted by the next `generator.bat` run while every happy-path test stays green. |
| Dart package ↔ native-assets build cache | `.dart_tool/hooks_runner/` keys on a checksum that does not cover the hook's own defines, so a stale cache can run the suite against the previous ABI. |
