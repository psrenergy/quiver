<user_story>
**As a** consumer installing a Quiver binding against a native library from a different release,
**I want to** be refused at load time with the struct name and both byte counts,
**so that** a layout skew is a startup error I can act on rather than a silent out-of-bounds
write discovered days later in an unrelated metadata read.
</user_story>

gate that consumes the accessors can be deleted without a single test noticing (Gap 2).

<assumption_delta_decision>
**Noun that is now primary:** "every FFI struct a binding hand-allocates a buffer for" --
displacing "the three structs the gates check" (options, scalar metadata, group metadata).

**Decision: `promote`.**

Rationale: SAFE-01's own wording was already the general rule ("**each** FFI struct a binding
allocates a buffer for"); the three-struct list was an implementation shortcut that the
verification correctly read as an incomplete implementation, not as a narrower requirement. Adding
`quiver_csv_options_t` as a fourth special case would leave the same hole open for the fifth
struct. So the gate list is promoted to the general rule, and the rule is written down in
`src/c/CLAUDE.md` and `bindings/js/CLAUDE.md` (02-10) as: *every C struct a binding allocates a
raw buffer for gets a `*_sizeof` accessor, a `static_assert`, and an entry in all four load-time
gates -- in one fixed order.*

**What this obliges later:** Phase 3 introduces a new attribute-metadata struct with its own size
constant (META-03). Under the promoted rule it joins the gate list by default; it is not a
decision to revisit. Phase 3's planner must add it to the fixed order rather than treat the
four-struct list as closed.
</assumption_delta_decision>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| native library ↔ binding process | A binding hand-allocates a buffer sized by a constant it holds, and hands the address to C. The native library writes into it using its own compiled layout. A disagreement is an out-of-bounds write inside the caller's address space. |
| installed package ↔ installed native | A wheel, npm package or artifact can be paired with a native library from a different release (partial upgrade, stale S3 artifact, `QUIVER_LIB_DIR` override). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-08-01 | Tampering | `quiver_csv_options_t` buffer allocated by `bindings/js/src/csv.ts` and declared by three other FFI layers | high | mitigate | `quiver_csv_options_sizeof()` + `static_assert(... == 56)` + a fourth entry in every load-time gate (this plan for the native half and Python; 02-10 and 02-11 for the rest). |
| T-02-08-02 | Tampering | `bindings/python/src/quiverdb/_loader.py` load-time gate | high | mitigate | Restore both call sites, and make removal detectable via `_CHECKED_STRUCTS` plus the mutation criterion in Task 1. The defect is not hypothetical: it is committed in HEAD. |
| T-02-08-03 | Denial of Service | A consumer who never touches metadata still hard-fails on any skew | low | accept | Deliberate, per D-08: a silent stride bug is worse than a loud refusal. Recorded, unchanged by this plan. |
| T-02-08-04 | Information Disclosure | The mismatch message reports two byte counts and a struct name | low | accept | Struct sizes are public header information; no secret is disclosed. |

No package-manager install task exists in this plan (no `npm install`, `pip install` or `cargo add`),
so the package-legitimacy gate does not apply and no `T-02-08-SC` entry is minted.
</threat_model>
