<user_story>
**As a** consumer of any Quiver binding,
**I want to** trust that `has_ui_config()` answers honestly in my host language for a broken
sidecar and an in-memory database, and that the config-path and locale parameters work on every
factory I might use,
**so that** I do not discover a per-binding behavioural difference in production that the C++
suite alone could never have caught.
</user_story>

<objective>
Close Gap 5 and Gap 7: the behaviour is already correct in every layer (the verifier proved it by
probe), but it is **committed as tests only in C++**. This plan turns six probe-proven behaviours
into six committed suites.

Purpose: `tests/CLAUDE.md` requires a cross-layer feature to add cases to the C++ suite, the C API
suite and all five binding suites. OPT-01/02/03/04 currently satisfy that for the happy path only
-- malformed polarity, the `:memory:` distinction (D-01, the user decision this phase was built
around), `open`/`from_migrations`, and whole-database `describe()` are all C++-only or
probe-only. A behaviour proven once by an ad-hoc probe and never committed regresses silently.

Output: no production code changes. Six test files gain cases against the **existing** shared
fixtures `tests/schemas/ui/malformed` and `tests/schemas/ui/foresight_like` -- no new fixture is
needed and none may be copied into a binding.

Wave note: this plan needs nothing from 02-08 behaviourally -- every surface it tests already
ships. It sits in wave 2 purely because it edits `tests/test_c_api_database_options.cpp`, which

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller-supplied `ui_config_dir` ↔ filesystem | A caller names any directory on disk; the parser reads TOML from it. This is deliberate (OPT-01 exists because claw's config is outside `<db_dir>`). |
| untrusted TOML content ↔ C++ parser | A malformed or hostile sidecar reaches `tomlplusplus` and the `UIConfigSet` builder. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-09-01 | Denial of Service | `require_ui_config()` reading a malformed sidecar | medium | mitigate | Already mitigated in 02-01 (degrade + warn, never throw, publish nothing partial). This plan adds the committed regression tests in six layers that keep it mitigated. |
| T-02-09-02 | Information Disclosure | An explicit `ui_config_dir` can point anywhere the process can read | low | accept | Deliberate and required by OPT-01. The C++ API intentionally imposes no sandbox — the caller chose the path. The Lua layer's own file operations remain sandboxed by the standing `resolve_sandboxed_path` policy, which this plan does not touch. Canon path-traversal hardening is not minted here (see the prohibition breadcrumb below). |
| T-02-09-03 | Tampering | A binding copying a fixture into `bindings/` and drifting from the shared corpus | low | mitigate | `DatabaseUiCorpus.FixturesAreNeverCopiedIntoABinding` already fails on this; the acceptance criteria re-assert it. |

Canon-referral breadcrumb (dropped, not minted): path-traversal / directory-escape hardening for
`ui_config_dir` is canon security guidance and is deliberately not applied — OPT-01 exists
precisely to let a caller escape `<db_dir>`, and the Lua sandbox already covers the one layer where
escape is a threat.

No package-manager install task exists in this plan, so no `T-02-09-SC` entry is minted.
</threat_model>
