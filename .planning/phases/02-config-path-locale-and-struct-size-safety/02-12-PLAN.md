<user_story>
**As a** Bun consumer who upgraded the `quiverdb` npm package but whose postinstall left an older
native library in place,
**I want to** be told my native library is stale and which exports it lacks,
**so that** I reinstall the native rather than chasing a "Cannot load native library" message that
tells me to install one I already have.
</user_story>

<objective>
Close Gap 3 and Gap 4 — the two JS-only defects the verification proved but could not reach through
the public API.

Gap 3: a native library predating Phase 2 has the full Phase 1 surface but **none** of the
`*_sizeof` exports, and since Phase 2 introduces them, **no already-published native has them** —
so this is the only skew that can actually occur today. Python, Dart and Julia each diagnose it.
JS cannot: Bun's `dlopen` resolves every declared symbol eagerly and throws when one is absent, and
`openLibrary()` is only reached from inside `initLibrary()`'s three swallowing tiers, so the load
dies before `assertNativeStructSizes` runs and surfaces as `Cannot load native library
'libquiver_c.dll'. Searched: …` — no struct name, no byte count, and it points the user at
"install the native library" rather than "your native library is stale".

Gap 4: `makeDefaultOptions`'s keepalive array is a genuine lifetime defect (proven on a
byte-for-byte replica with `Bun.gc(true)` in the window), even though 3000 iterations through the
public API produced 0 failures.

Purpose: both are in the same two files, so they share a plan and a wave. This plan is separated
from 02-10 because both plans edit `loader.ts` and `ffi-helpers.ts`.

Output: a tiered loader parameterized by symbol map with a probe-based skew diagnosis, and an
options buffer that has no second allocation to lose.
</objective>

<design_decisions_recorded_here>
**Gap 3 — chosen shape: probe, not catch-and-annotate.** The report named two candidates. Catching
`initLibrary`'s failure and re-throwing with a version-skew message is rejected: `initLibrary`
already collapses three distinct failure paths into one `lastError`, so an annotated message could
only say "maybe your native is stale" and would say it just as loudly when no native exists at all
— turning a precise not-found into a vague guess. The probe distinguishes the two cases: if the
same tiered resolution succeeds with a symbol map containing only a symbol that has existed since
before this milestone, the library is present and loadable and the full-map failure was a missing
symbol. That is a determination, not a guess.

**Gap 4 — remedy 2 rejected as unnecessary, explicitly.** Reading `OPTIONS_SIZE` from the accessor
at allocation time is **not** adopted. The verification's own caveat is correct: `getSymbols()`
runs the gate and provably precedes `makeDefaultOptions` at all three call sites, so no options
buffer can be allocated before the accessor has confirmed 24. Per-allocation accessor reads would
add an FFI call per database open for zero additional safety. The pinned literal stays, guarded by
the load-time gate.

**Gap 4 — remedy 1 implemented as elimination, not reinforcement.** Rather than bind the keepalive
harder, the child allocations stop existing: the option strings move into the tail of the struct
buffer itself. One allocation cannot lose a second one. `csv.ts`'s `buildCsvOptionsBuffer` keeps
its keepalive tuple — it genuinely needs many child allocations (pointer tables) and cannot
collapse — so the two functions diverge deliberately and that divergence is recorded in
`bindings/js/CLAUDE.md`.
</design_decisions_recorded_here>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| installed npm package ↔ postinstall-downloaded native | The JS binding fetches natives from S3 at install time. A partial or cached install pairs a new package with an old native — and since Phase 2 introduces the `*_sizeof` exports, *every* already-published native is old in exactly this way. |
| JS garbage collector ↔ native call window | A `Uint8Array` whose address was passed to C is not pinned by Bun. Anything reachable only from a local that the engine can prove dead may be collected while C still holds its address. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-12-01 | Tampering | `makeDefaultOptions` child string allocations collected inside the FFI window | medium | mitigate | Eliminate the child allocations: one self-contained buffer whose tail holds both strings, so the struct and its strings share a single lifetime. |
| T-02-12-02 | Spoofing | A stale native library misreported to the user as "not installed" | high | mitigate | `resolveLibrary`'s probe distinguishes present-but-stale from absent and throws a message naming the four missing accessors. |
| T-02-12-03 | Tampering | A future edit moving the struct-size gate inside a swallowing tier, remasking a real mismatch | high | mitigate | Position pinned by an acceptance criterion grepping `loader.ts`, and restated in `bindings/js/CLAUDE.md` including the new `resolveLibrary` frame. |
| T-02-12-04 | Information Disclosure | The skew message lists native export names | low | accept | Export names are public header information. |

No package-manager install task exists in this plan (no new npm dependency), so no `T-02-12-SC`
entry is minted and no RESEARCH package-legitimacy audit is required.
</threat_model>
