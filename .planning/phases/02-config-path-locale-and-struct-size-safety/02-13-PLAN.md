<release_impact_analysis>
**Does adding `quiver_csv_options_sizeof` change the release story 02-07 already planned?** No.

02-07 planned a single Bump Version dispatch with `part=minor`, yielding 0.11.0. That number is
unchanged: `scripts/assert_version.py` computes a minor bump as `{major}.{minor+1}.0`, so 0.10.7
→ 0.11.0 exactly as 0.10.6 → 0.11.0 would have. The release is already breaking (the options
struct grew 8 → 24 bytes), so a minor bump is already correct under the `0.x` convention.

A new export is **additive**, not breaking: no existing symbol is removed, no existing struct
changes size or field order, and a consumer built against the previous header still links. It
therefore adds no second bump and no second dispatch. What it does require is a **CHANGELOG line**:
the 0.11.0 entry currently names three size accessors and must name four, because the release notes
are the only place a hand-written FFI consumer learns the accessor exists.

The dispatch itself stays deferred until Phase 3 lands, exactly as STATE.md's Pending Todos
records. This plan does not dispatch it.
</release_impact_analysis>
