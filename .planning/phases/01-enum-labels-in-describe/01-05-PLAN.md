<objective>
**As a** consumer reading Quiver's reports through the C API or through an embedded Lua script,
**I want to** the enum rendering to be proven at my own boundary, **so that** a marshalling bug that
truncates or re-encodes a label fails in the layer that introduced it rather than silently reaching
me.

DESC-07 requires exact-string assertions from every layer, not "a String was returned". This plan
covers the two layers that are C++ gtest files and can therefore share the fixture helper built in
plan 01-01: the C API suite and the Lua suite.

Purpose: prove the report crosses the `char**` boundary and the sol2 boundary byte-for-byte,
including the non-ASCII case the C++ core suite can never see.

Output: `tests/test_c_api_database_describe.cpp` and new cases in
`tests/test_lua_runner_describe.cpp`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| C++ `std::string` → C `char*` → caller | `quiver::string::new_c_str` copies the report across the FFI boundary; a truncation or re-encoding here reaches every binding. |
| C++ `std::string` → sol2 → Lua string | sol2 copies the report into a Lua byte string; the same failure class applies with a different mechanism. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-18 | Tampering | `char**` report marshalling | high | mitigate | `NonAsciiLabelBytesSurviveMarshalling` asserts an accented UTF-8 byte sequence end to end, which is the only assertion in the repo that would catch a length-based truncation of a multi-byte label. |
| T-01-19 | Tampering | sol2 string copy | high | mitigate | `NonAsciiLabelSurvivesSol2` is the same check at the Lua boundary; Lua strings are byte strings, so a re-encoding bug shows as a byte mismatch. |
| T-01-20 | Spoofing | assertion that passes for the wrong reason | medium | mitigate | Every Lua assertion uses `string.find(..., 1, true)` so `{`, `}`, `(`, `)` and `-` are matched literally rather than as Lua patterns; a pattern-mode assertion would match strings the renderer never produced. |
| T-01-21 | Denial of Service | leaked report allocations in the C API suite | low | mitigate | Every case frees with `quiver_database_free_string` and closes its handle; the acceptance criteria count the frees against the report calls. |
| T-01-SC | Tampering | package installs | n/a | accept | No package manager runs in this plan. |
</threat_model>
