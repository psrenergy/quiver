## Resolved tensions (read before starting)

**1. "Zero public surface" vs. `has_ui_config()`.** CONTEXT.md `<domain>` says "no public header
change"; D-22 says `has_ui_config()` is C++-only in Phase 1; PARSE-11 requires it to answer.
The binding reading is D-22's: the constraint that ships this as a patch is **no ABI break, no new
C symbol, no binding source change**. `Database` is a Pimpl class, so adding a non-virtual
`bool has_ui_config() const;` adds one exported C++ symbol to `libquiver` and changes no struct
layout, no vtable and no C ABI. That is ABI-additive and patch-safe. It is the *only* public
header edit this phase makes.

**2. D-29 (one database filename per suite) is tightened, not weakened.** D-29's intent is that
seven suites never collide in the shared fixture directory. `gtest_discover_tests` registers every
`TEST` as its own ctest test, so `ctest -j` can run two C++ cases against the same directory
concurrently. The fixture helper therefore takes a per-test database **stem**
(`cpp_enum_basic`, `cpp_malformed`, …) rather than one `cpp.sqlite` for the whole suite. Same
intent, strictly stronger.

**3. Gitignore discipline (D-29's "accepted consequence") is already free.** Root `.gitignore`
carries `*.db`, `*.sqlite` and `*.log` globs, so generated fixture artefacts are ignored with no
new entry. Do not add one.

Create `src/ui_config.cpp` implementing the above with `toml++`:
- `from_directory` parses `<ui_dir>/main.toml`, reads its `collections` array, and for each entry
  parses `<ui_dir>/<entry>.toml`. It **never** enumerates `*.toml` to decide what to load
  (PARSE-01); it enumerates the directory only to fill `unlisted_files` with `.toml` files whose
  stem is neither `main`, `enum`, nor a listed entry.
- `<ui_dir>/enum.toml` is optional: a missing file leaves `vocabularies` empty without error, and
  every top-level key is a vocabulary name whose value is an array-of-tables of `{id, label}`.
  Iterate `toml::table`'s own keys — the vocabulary names are not known ahead of time. `id` reads
  as `int64_t`, `label` through the localizable resolver.
- Localizable resolution, copied from Hub's `LocalizationString.ofLocale`: a bare string wins
  outright and ignores locale; otherwise exact `locale` key, then `"en"`, then the first key in

  throw). An empty table and an explicitly empty string both yield `""`.
- Per-attribute keys consumed: `id`, `label`, `tooltip`, `unit`, `hide`, `enum` (into
  `vocabulary`) and `format`; `format` is read verbatim as a single string for now (its 4-key

  declares. `label` is never back-filled from `id` (D-12) — `configured` is the discriminator.
- `[[attribute_group]]` entries are read into `UICollectionConfig::groups` with the same
  `UIMetadata` record, keyed by their own `id`, in whatever order they appear.
- Collection-level `label`/`icon`/`tooltip` land on `UICollectionConfig::meta`, and
  `display_order` is the collection's index in `main.collections` (GROUP-02 consumes it in Phase 4;
  recording it here is free and keeps the parse single-pass).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `<db_dir>/ui/*.toml` → parser | Untrusted file content crosses here. The files ship with a "trusted" model repo, but a truncated, corrupt or adversarially-crafted one must never crash the process or leave half-initialised state behind. |
| parser → report string | Attacker-influenced label bytes are concatenated into a string every downstream agent reads. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Denial of Service | `Impl::require_ui_config` | high | mitigate | `catch (const std::exception&)` around the whole `from_directory` call; `toml::parse_error` derives from `std::runtime_error`, so one catch covers parse, filesystem and bad-type failures. Pinned by `MalformedSidecarPublishesNothing`. |
| T-01-02 | Tampering | `Impl::require_ui_config` | high | mitigate | Publish-nothing-until-valid: `ui_config` is assigned as the last statement inside the `try`, so a throw mid-walk cannot leave a half-loaded config that the next call reads as authoritative. |
| T-01-03 | Information Disclosure | `require_ui_config` on `:memory:` | medium | mitigate | `:memory:` short-circuits before any directory computation, so no database can be made to read `ui/` relative to the process working directory. |
| T-01-04 | Spoofing | enum label rendering | medium | mitigate | The code is always rendered beside the label and an unmatched code renders `(undeclared)`, so a wrong or missing label cannot masquerade as authoritative ground truth. Standing mitigation for the milestone's accepted risk until Phase 5. |
| T-01-05 | Tampering | path traversal via `main.collections` | low | accept | Collection filenames come from `main.toml`, joined with `fs::path(dir) / (name + ".toml")`. A hostile `main.toml` implies write access to the database file's own directory, so no new trust boundary is crossed. Revisit at OPT-01 (Phase 2), when a caller may supply an arbitrary UI directory. |
| T-01-SC | Tampering | package installs | n/a | accept | No package manager runs in this phase. `tomlplusplus` v3.4.0 is pre-existing, vendored via CMake FetchContent and already linked `PRIVATE` on the `quiver` target — no npm/pip/cargo install, so the legitimacy gate does not apply. |
