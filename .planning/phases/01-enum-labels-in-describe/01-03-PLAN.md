<objective>
**As a** coding agent calling `describe` on a PSR model database, **I want to** read each scalar's
label, unit, hidden flag and full enum vocabulary in one report, **so that** a single call tells me
what every column means without a second round trip.

The tracer proved the path on one clause. This plan builds the rest of the rendering out from it:
the header line, the collection label, and the four scalar-line clauses — all append-only, all
guarded on non-empty, all through the one shared renderer.

Purpose: deliver the agent-facing surface DESC-02, DESC-03, DESC-04 and DESC-06 describe, while
keeping DESC-05's byte-identical guarantee green against the goldens plan 01-01 captured from
unmodified code.

Output: `src/database_describe.cpp` render clauses and their exact-string assertions.
</objective>

In `write_collection_section`'s scalar loop, after the existing `PRIMARY KEY` / `NOT NULL` output
and before the newline, append four independently guarded clauses in this exact order (D-02):

1. **unit** — when the attribute has a record with a non-empty `unit`, write a space then the unit
   in square brackets: ` [MW]`.
2. **hidden** — when the record's `hidden` is true, write ` [hidden]`. DESC-06: the attribute is
   tagged, never filtered out; hiding is a GUI affordance and an agent reading the schema wants it.
3. **label** — when the record's `label` is non-empty, write a space, `kEmDash`, a space, then the
   label in double quotes. An empty label means the sidecar declares none and produces no clause;
   the attribute id is never synthesised into it (D-12).
4. **vocabulary** — when the record's `vocabulary` is non-empty, write ` enum <name>`, then:
   - if `find_vocabulary` resolves it, ` {` followed by every declared entry as `<code>: <label>`
     joined by `, ` in **enum.toml declaration order**, then `}`. This is DESC-03's full declared
     value list — it comes from the vocabulary, so a code no row uses still appears.
   - if it does not resolve, ` (undeclared vocabulary)`. The binding is reported and its absence is
     named; nothing is invented. This is the read-side half of the milestone's accepted-risk
     posture, and Phase 5's VALID-02 turns the same condition into a validator finding.

Every clause reads through `find_attribute(*ui, collection, name)`, which returns `nullptr` when
there is no config, no collection entry or no attribute entry — so the whole block is skipped and
today's line is emitted unchanged. That is what makes DESC-05 hold by construction.

Leave `summarize_collection`'s scalar line alone apart from the histogram labels already added by
the tracer: DESC-01 asks only for labels in the histogram, and keeping that line otherwise
untouched is what keeps the existing negative assertion about a float column carrying no value
distribution meaningful.
