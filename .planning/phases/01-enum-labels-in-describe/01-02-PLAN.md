subdirectory. Every file is a hand-written miniature, LF line endings, UTF-8 without BOM. Each
directory pins exactly one rule unless a real model file genuinely carries several.

`bess_like/` — CORPUS-01 (BESSOperation), PARSE-03, PARSE-07, PARSE-08. Collection `Storage`.
`ui/main.toml` lists `["storage"]`. `ui/enum.toml` declares a `look_ahead` vocabulary with **all
bare-string** labels and **gapped, non-zero-based, negative and large** codes — use ids `-1`, `0`,
`3`, `7` and `9223372036854775807` so both the gap tolerance and the int64 range are data-pinned.
`ui/storage.toml` sets `id = "Storage"` and interleaves, in this order: `[[attribute_group]]` with
`id = "degradation"`, then `[[attribute]]` with `id = "degradation"`, then `[[attribute_group]]`
with `id = "rte"`, then two more `[[attribute]]` blocks — reproducing the real file's shape. Every
label in this directory is a bare string.
**The schema must make the collision real, not notional:** `schema.sql` creates `Storage` with a
scalar column named `degradation` **and** a vector group table `Storage_vector_degradation`, plus a
`Storage_vector_rte` for the second group. Without both, `degradation` is an id collision only in
the TOML and PARSE-07 cannot be observed through `describe_collection`. Give the two `[[attribute]]`
blocks that follow a group block distinct labels so PARSE-08's "still parsed after a group block"
is assertable.

`foresight_like/` — CORPUS-01 (Foresight), PARSE-04. Collection `EconomicDriver`.

`htd_like/` — CORPUS-01 (HydroThermalDispatch), PARSE-10. `ui/main.toml` lists `["hydro_plant"]`;

`format_table/` — PARSE-06. One attribute whose `format` is the 4-key table form

`orphan_collection/` — PARSE-01. `ui/main.toml` lists `["storage"]` only; `ui/agent.toml` is a
