## D-31 — the written call the roadmap demands

CONTEXT.md leaves D-31 to the planner and the roadmap requires an explicit, recorded decision. It is:

**Strengthen and keep.** The four binding describe suites gain genuine exact-string assertions
against `tests/schemas/ui/` fixtures, and their existing `isA<String>` / `isa String` /
`typeof === "string"` / `isinstance(..., str)` cases **stay**. The reasoning is not sentiment:
those four cases are the only per-binding assertion that `describe`, `describeCollection` and
`summarizeCollection` still work on a sidecar-less `:memory:` database — which is DESC-05's
binding-side guard, and nothing else in this phase covers it from a binding. They cost nothing to
keep and they cover a case the new fixtures deliberately do not.

What is deleted is the **comment** each file carries — "the binding only verifies each method
returns a string; the report content is covered by the C++ core tests". That sentence was true
until this phase and DESC-07 makes it false. Leaving it would tell the next reader not to add the
very assertions this plan is adding.

Until this plan lands, the four suites are **not** five-layer coverage and must not be counted as
such. After it lands, they are.

## Resolved tension — "no file under bindings/ changed" vs. DESC-07

Success Criterion 5 says `git diff` shows no file under `bindings/` changed. DESC-07 requires new
tests in all five bindings, which necessarily live under `bindings/*/test*/`. These are not in
conflict, and the correct reading is CONTEXT.md's own wording in `<domain>`: **"no file under
`bindings/src`"**. The constraint is about binding *source* — loaders, decoders, generated FFI
files, manifests — because that is what makes this a patch with no ABI change and no republish of
hand-mirrored layout constants. Binding *tests* are not part of that surface.

The gate in Task 3 therefore checks binding paths **excluding** test directories, and it is written
that way deliberately so the phase cannot fail its own criterion on a technicality. The stricter
half — that no loader, decoder, manifest or generated file changed — is checked in full.
