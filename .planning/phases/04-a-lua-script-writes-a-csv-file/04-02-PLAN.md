<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Lua script to filesystem | A script-supplied path string crosses into `std::ofstream`. The sandbox root is the directory containing the database file. |
| Lua script to C++ writer | Arbitrary Lua values (tables, functions, userdata, non-finite numbers, invalid UTF-8 byte strings) cross into the cell formatter. |
| Emitted file to downstream consumer | The CSV leaves Quiver and may be opened by a spreadsheet or another parser outside Quiver's control. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Tampering | `db:write_csv` path argument (`src/lua_runner.cpp`) | high | mitigate | Route the path through the existing `resolve_sandboxed_path` choke point unchanged and before the options decode (LUA-10). This plan's precedence test is the assertion that the order holds. Add no new path logic. |
| T-04-02 | Tampering | Any existing file inside the sandbox (the live `.db`, a `.qvr`, a migration `.sql`) | high | accept | A destructive-overwrite guard is explicitly declined in `.planning/REQUIREMENTS.md` section Out of Scope: `db:open_file('w')` already has the identical hole, the project assumes callers obey contracts, and WRITE-08 documents the truncation instead. Accepted at project level; do NOT add a guard here. |
| T-04-03 | Tampering | Emitted cell content (CSV/formula injection) | medium | accept | Quiver performs no inference or rewriting of cells in either direction (REQUIREMENTS section Out of Scope, "Numeric or date inference on cells"), and an escape prefix would break the byte-identical round trip every criterion in this phase asserts. The downstream spreadsheet is outside Quiver's trust boundary. |
| T-04-04 | Information disclosure | Pattern 1 error messages from `write_csv` / `write_row` / `close` | low | mitigate | This plan's messages quote the caller's own path spelling (`original_path`), never the resolved absolute path, plus the sandbox root in the escape message - exactly the two values `resolve_sandboxed_path` and `csv_read::Reader` already disclose. The `std::error_code` message text from a failed directory check is an OS reason string, the same class `resolve_sandboxed_path` already surfaces. |
| T-04-05 | Denial of service | Unbounded output from a script loop | low | accept | The script controls its own loop; `std::ofstream` streams rather than buffering the whole file. No quota exists anywhere in the Lua sandbox today and none is introduced. |

No package-manager install task exists in this phase - the writer is hand-rolled with no new
dependency by explicit decision - so there is no `T-04-SC` supply-chain entry and no Package
Legitimacy Audit is required.
</threat_model>
