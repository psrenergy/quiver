<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Lua script to filesystem | A script-supplied path string crosses into `std::ofstream`. The sandbox root is the directory containing the database file. |
| Lua script to C++ writer | Arbitrary Lua values (tables, functions, userdata, non-finite numbers, invalid UTF-8 byte strings) cross into the cell formatter. |
| Emitted file to downstream consumer | The CSV leaves Quiver and may be opened by a spreadsheet or another parser outside Quiver's control. |
| Reference text to every agent session | `LUA_DB_API_REFERENCE` is interpolated into every `claw` system prompt; a wrong example teaches a wrong pattern on every session. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Tampering | `db:write_csv` path argument (`src/lua_runner.cpp`) | high | mitigate | The path routes through the existing `resolve_sandboxed_path` choke point unchanged. This plan's tests write only into the `LuaSandboxTest` per-test temp directory, so no fixture escapes it. |
| T-04-02 | Tampering | Any existing file inside the sandbox (the live `.db`, a `.qvr`, a migration `.sql`) | high | accept | A destructive-overwrite guard is explicitly declined in `.planning/REQUIREMENTS.md` section Out of Scope: `db:open_file('w')` already has the identical hole, the project assumes callers obey contracts, and WRITE-08 documents the truncation instead. Accepted at project level; do NOT add a guard here. |
| T-04-03 | Tampering | Emitted cell content (CSV/formula injection) | medium | accept | Quiver performs no inference or rewriting of cells in either direction, and an escape prefix would break the byte-identical round trip every assertion in this plan makes. The downstream spreadsheet is outside Quiver's trust boundary. |
| T-04-06 | Spoofing | The worked example in `LUA_DB_API_REFERENCE` | medium | mitigate | The example is extracted from the reference file at test time and executed, so a plausible-but-wrong example cannot ship. A transcribed copy in the test would reintroduce exactly the drift this mitigates. |
| T-04-05 | Denial of service | Unbounded output from a script loop | low | accept | The script controls its own loop; `std::ofstream` streams rather than buffering the whole file. No quota exists anywhere in the Lua sandbox today and none is introduced. |

No package-manager install task exists in this phase - the writer is hand-rolled with no new
dependency by explicit decision - so there is no `T-04-SC` supply-chain entry and no Package
Legitimacy Audit is required.
</threat_model>
