Fixture shape, copied from `MigrationsTestFixture` in `tests/test_migrations.cpp`: a base class
`UiTempTreeFixture` whose `SetUp` computes `root = fs::temp_directory_path() / "quiver_ui_metadata_test"`
and `fs::remove_all(root)` if present, and whose `TearDown` does the same — clean on both ends so a
crashed prior run cannot leak. Expose three protected members and three helpers:

  - `std::string root;` — the per-test temp directory.
  - `std::string migrations_dir()` — `root / "migrations"`.
  - `std::string ui_dir()` — `root / "ui"`, the sibling `weakly_canonical(migrations_dir()).parent_path() / "ui"` resolves to.
  - `void write_migration(int version, const std::string& up_sql, const std::string& down_sql)` —
    `fs::create_directories(migrations_dir() / std::to_string(version))`, then writes `up.sql` and
    `down.sql` with `std::ofstream`.
  - `void write_ui_file(const std::string& filename, const std::string& contents)` —
    `fs::create_directories(ui_dir())`, then writes `ui_dir() / filename`. Callers pass raw string
    literals; the helper never synthesizes TOML itself.
  - `quiver::Database open_tree()` — `quiver::Database::from_migrations((fs::path(root) / "study.db").string(), migrations_dir(), {.read_only = false, .console_level = quiver::LogLevel::Off})`.

Derive two fixtures from it with the exact names the validation map's gtest filters need:
`class UiConfigTest : public UiTempTreeFixture {};` and
`class DatabaseUiMetadataTest : public UiTempTreeFixture {};`. Both are empty derivations — the two
names exist so `--gtest_filter=*UiConfig*` and `--gtest_filter=*DatabaseUiMetadata*` each select the
loader-facing and render-facing halves of one file.

`reservoir_type INTEGER`, `discount_rate REAL` — all `STRICT`. These are the columns every later
test's sidecar describes; keep the names exactly as written so plan 01 and plan 02 can assert against
them without re-reading this file.
