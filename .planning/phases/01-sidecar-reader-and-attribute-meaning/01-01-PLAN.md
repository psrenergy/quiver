**2. `src/ui_config.cpp` (new).** Implements `UiConfig::find` (two `find` calls on the nested maps,
`nullptr` on either miss) and `load_ui_config`. Include the parser header here and nowhere else.
Structure of `load_ui_config`, following D-09's nested try/catch exactly:

  - One outer `try` wrapping everything, with `catch (const std::exception& ex)` that calls
    `logger.warn("Failed to load UI metadata from '{}': {}", migrations_path, ex.what())` and
    `return {};` — an empty `UiConfig`, discarding any partial work. This is the `src/database.cpp`
    lines 69-86 posture, and is explicitly not `src/binary/binary_metadata.cpp`'s throwing posture.
  - Resolve `const fs::path ui_dir = fs::weakly_canonical(fs::path(migrations_path)).parent_path() / "ui";`
    Return an empty config immediately and **without warning** when `!fs::is_directory(ui_dir)` — an
    absent sidecar is the normal case (SAFE-01), not a degradation.
  - Vocabulary pass, before the collection pass. If `ui_dir / "enum.toml"` is a regular file, parse
    it inside its own inner try/catch (warn and continue on failure) and leave the result in a local
    `std::map<std::string, std::map<int64_t, std::string>> vocabularies`. Task 1-01-02 fills this
    pass in; for this task, leave the pass declared and the map empty so the seam exists and the
    enum field stays default-constructed.
  - Collection pass: a non-recursive `fs::directory_iterator(ui_dir)` loop. Skip anything that is not
    `is_regular_file()`, anything whose `extension()` is not `".toml"`, and the single filename
    `enum.toml` (already consumed by the vocabulary pass — skipping it avoids a second parse and a
    duplicated warning; it would also be rejected by the shape gate below, which remains the only
    *selector*). Each surviving file is parsed inside its own inner try/catch whose handler warns
    naming that file's path and `continue`s, so one malformed file costs only its own collection.
  - Shape gate (D-17 / READ-02): read the top-level `id` as an optional string and the top-level
    `attribute` key as an array. Skip the file unless both are present and `id` is non-empty. This is
    what excludes `main.toml` (no `id` key at all) and every theme file, with no filename translated
    into a table name.
  - For each element of the `attribute` array that is a table: read its own `id` as an optional
    string, skip the entry when absent or empty; read `label` and `tooltip` through the shared
    localizable accessor below; store with `collections[*file_id][*attr_id] = std::move(meta);`
    so a repeated attribute id resolves to the later entry. Read **only** `attribute`; never
    `attribute_group` (D-18 — 15 corpus files reuse one id across both arrays).
  - Shared localizable accessor (READ-04), one static function serving `label`, `tooltip` and later
    each vocabulary entry's own `label`: given a node pointer, return `std::nullopt` for a null node;
    return the value when it reads as a string; otherwise, when it is a table, return its `en`
    sub-key read as a string; otherwise `std::nullopt`. Zero of 817 corpus locale tables lack `en`,
    but degrade rather than throw.
  - Every read in this file uses the optional-checked form — the templated `value<T>()`, `as_array()`,
    `as_table()` — and is checked before dereference. The zero-argument unwrap on the returned
    optional is forbidden anywhere in this file; it is the exact crash-on-missing-key posture D-09
    exists to prevent.

**6. `src/database_describe.cpp`.** Add three static helpers to the existing anonymous namespace,
then the clause emitter, then change the signature and both callers.

  - `std::string normalize_ui_text(const std::string& raw)` (D-03, and the T-01-03 mitigation):
    map every byte for which `static_cast<unsigned char>(c) < 0x20 || static_cast<unsigned char>(c) == 0x7F`
    to a space — a deliberate superset of D-03's named `\r`/`\n`/`\t` that also neutralizes ESC
    (0x1B) and every other C0 control, so no sidecar string can emit an ANSI escape sequence into a
    terminal rendering the report. Then collapse runs of spaces to one and trim both ends. Testing
    the byte as `unsigned char` is what keeps UTF-8 intact: every byte of a multibyte sequence is
    0x80 or above and is never touched. An empty result means the value is **absent** and no clause
    is emitted — never an empty pair of quotes. Normalizing here rather than trusting the loader
    makes one-line-per-attribute a property of the writer.
  - `std::string quote_ui_text(const std::string& text)` (D-02): return the text wrapped in ASCII
    double quotes with each backslash doubled and each double quote backslash-escaped, and no other
    escaping. This is what makes every separator unambiguous — arbitrary user text only ever appears
    between an unescaped opening and closing quote, and real corpus labels contain commas, colons,
    semicolons, parentheses, brackets and braces.
  - `std::string squash(const std::string& s)` (D-04): for each character, lowercase it with the
    explicit ASCII test `c >= 'A' && c <= 'Z' ? c + 32 : c`, then keep it only when it is in `a`-`z`
    or `0`-`9`. Spell it exactly that way — passing a negative `char` to the standard lowercase
    function is undefined behavior and 344 corpus strings are non-ASCII UTF-8. The consequence is
    that squash drops non-ASCII bytes, which biases toward *printing* a label; that is the safe
    direction and is deliberate. Add a comment saying so, so it is not later "corrected".
  - `void write_ui_clauses(std::ostream& out, const UiAttribute* meta, const std::string& name, bool with_tooltip)`
    (D-01): returns immediately when `meta` is null. Otherwise, in this fixed order and with each
    clause carrying its own leading `"; "` so eliding one leaves no dangling separator:
    (a) the label clause `"; label "` plus the quoted normalized label, emitted only when the
    normalized label is non-empty and `squash(normalized_label) != squash(name)`;
    (b) the enum clause — no-op in this task, added by 1-01-02;
    (c) the tooltip clause `"; tooltip "` plus the quoted normalized tooltip, emitted only when
    `with_tooltip` is true, the normalized tooltip is non-empty,
    `squash(normalized_tooltip) != squash(name)`, and `squash(normalized_tooltip) != squash(meta->label)`
    — that last comparison against the **raw sidecar label**, per D-05, even when the label clause
    was itself suppressed.
    Only the tooltip clause is conditional on `with_tooltip`; label and enum are unconditional. That
    is what makes `describe()`'s line a strict prefix of `describe_collection()`'s by construction.
  - Change `write_collection_section`'s signature to
    `void write_collection_section(std::ostream& out, const Schema& schema, const std::string& collection, int64_t count, const UiConfig* ui, bool with_tooltip)`.
    In the scalar loop, replace the standalone final `out << "\n";` with a call to `write_ui_clauses`
    passing `ui ? ui->find(collection, name) : nullptr`, followed by the same `out << "\n";`.
    Everything before it — the `"    - "` prefix, the name, the parenthesized type, `PRIMARY KEY`,
    `NOT NULL` — is untouched, which is what keeps the pinned `"    - <name> "` prefix and the
    existing lifecycle assertions intact.
  - `Database::describe()` passes `&impl_->ui_config, false`; `Database::describe_collection()`
    passes `&impl_->ui_config, true`. Leave `summarize_collection` completely untouched — its
    annotation is Phase 2.
