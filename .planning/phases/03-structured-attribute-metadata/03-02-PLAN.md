`quiver_database_free_ui_metadata` declaration 03-01 added, so the whole UI-metadata surface sits in
one block:

— a plain string array, freed by the **existing** `quiver_database_free_string_array(char**, size_t)`.

single string array already has a generic free that every binding decodes today.

char*** out_labels, size_t* out_count)` — the two-parallel-array shape D-11 fixed, modelled directly
on `quiver_database_read_time_series_files`'s declaration.

`quiver_database_free_ui_vocabulary(int64_t* codes, char** labels, size_t count)` — the dedicated
combined free D-37 requires. Comment the declaration with the reason it exists rather than composing
`free_integer_array` + `free_string_array`: a decoder that frees one array and forgets the other
leaks with nothing to catch it, and the caller would have to hold `count` alive for the second call.
Cite `quiver_database_free_time_series_files` as the in-repo precedent.

Implement all three in `src/c/database_metadata.cpp`, appended after the single-record getter, using
the file's existing `QUIVER_REQUIRE` + try/catch + `quiver_set_last_error` shape. The allocation
bodies copy `quiver_database_read_time_series_files`'s loop from
`src/c/database_time_series.cpp:397-476` — one `malloc` per array sized by the entry count, `strdup`
per label, direct assignment per code — with the only difference being that the first array holds
`int64_t` rather than `char*`. A zero-entry vocabulary must still succeed: set `*out_count` to zero
and either allocate zero-length arrays or set the out-pointers to NULL consistently with what the
time-series precedent does for an empty result, and make the free tolerate whichever choice is made.
The combined free releases every label with `free`, then both arrays, and returns `QUIVER_OK`; it
must accept NULL for either array so a partially-populated or empty result is safe to free.

Do not touch `quiver_scalar_metadata_t`, `quiver_group_metadata_t`, or any of their functions
(D-16, ROADMAP criterion 4). Do not add a `quiver_ui_enum_entry_t` struct — D-10 and D-11 settled
that the entries cross as parallel arrays, not as a second struct, and a second struct would mean a
sixth entry in every binding's size gate.
