  <action>
Add three static converter/getter pairs to `src/lua_runner.cpp`, beside the existing metadata block.

`ui_metadata_lua(const UIMetadata&, sol::this_state)` builds the record table. `configured` and
`hidden` are always present as booleans and `display_order` is always present as an integer — they
are the discriminators and have real false/-1 values. The six text fields are set **only when
non-empty**; an empty one leaves the key absent, which is what `sol::lua_nil` already does for
`scalar_metadata_lua`'s `default_value`. This is D-38 and it is the one layer where D-13's
"empty string means absent" does not hold: `""` is truthy in Lua, so handing it over would make the
idiomatic `if md.unit then` guard fire for every attribute in the database — the same trap
`db:read_csv`'s header handling already avoids. Note in a comment that this divergence is recorded
in root `CLAUDE.md`'s per-binding divergence list (plan 03-07 writes that entry).

`ui_vocabulary_lua(const std::vector<UIEnumEntry>&, sol::this_state)` builds a 1-based `sol::table`
whose element `i` is a table with `code` and `label`, copying `dimension_to_lua`'s shape. Do **not**
build a code-keyed map: the JSON return encoder turns a table keyed `1..n` into an array and
anything else into a lexicographically sorted object, so a code-keyed table's JSON shape would vary
with the data and, in the `1..n` case, drop the codes entirely (D-39).

Then the three thin getters — `get_attribute_ui_metadata_lua(Database&, const std::string&, const
std::string&, sol::this_state)`, `list_ui_vocabularies_lua(Database&, sol::this_state)` and
`get_ui_vocabulary_lua(Database&, const std::string&, sol::this_state)` — each calling the
corresponding C++ method directly and converting. Let the C++ exception propagate; sol2 surfaces it
as a Lua error carrying the core's message, and no message is crafted here.

Register all three in the metadata block with the literal receiver `bind`:
`bind.set_function("get_attribute_ui_metadata", &get_attribute_ui_metadata_lua);`,
`bind.set_function("list_ui_vocabularies", &list_ui_vocabularies_lua);`,
`bind.set_function("get_ui_vocabulary", &get_ui_vocabulary_lua);`. The `bind.set_function("<name>",`
spelling is what `lua-api-sync.test.ts`'s pass-1 regex scans for, so any other registration route
makes the name invisible to the sync gate.
