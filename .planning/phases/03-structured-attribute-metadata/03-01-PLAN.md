<corrections_carried>
Two recorded premises are wrong. This plan is written against the corrected version.

**Correction 1 — 03-CONTEXT D-43's "no CMake work" is wrong.** `src/CMakeLists.txt` carries
hand-maintained explicit source lists for both targets: the `QUIVER_SOURCES` `set()` at lines 2-38
for `quiver`, and the inline list inside `add_library(quiver_c SHARED ...)` at lines 118-138 for
`quiver_c`. There is no `file(GLOB ...)`. A new `.cpp` added to neither list silently never
compiles, and every dependent test then fails as an undefined-reference link error rather than a
missing-file error.

**This plan's answer is avoidance, not mitigation: it adds no new `.cpp` to either target.** The
three C++ getters join the existing `src/database_metadata.cpp` (102 lines — the file that already
holds `get_scalar_metadata`), and the C API surface joins the existing `src/c/database_metadata.cpp`
(186 lines — the file that already holds `quiver_database_get_scalar_metadata` and the two existing
`*_sizeof` accessors). `include/quiver/ui_metadata.h` is a header, not a compiled source, and
`src/CMakeLists.txt:112` installs `include/quiver/` recursively, so it needs no build-list entry
either. `src/CMakeLists.txt` is therefore expected to end this phase byte-identical. The one place
the hazard still bites is `tests/CMakeLists.txt`, whose test-source lists are equally explicit —
Task 3 carries an explicit nonzero-test-count criterion for exactly that reason.

**Correction 2 — Lua is not gated by the C-struct freeze.** `LuaRunner` calls `Database::…`
directly in C++ (`src/lua_runner.cpp`'s `get_scalar_metadata_lua` at :1645 calls
`db.get_scalar_metadata(...)` with no C API involvement), so the Lua surface depends only on the
C++ getter signatures this plan freezes — not on `quiver_ui_metadata_t`'s byte layout. Plan 03-06
is scheduled in the same wave as the four FFI decoders, not behind them.

**Correction 3 (found while planning, not in any prior artifact) — a new C header would cost three
generator-config edits, not one.** 03-CONTEXT D-43 budgets "one line in Python's 5-entry `HEADERS`
list" for a new `include/quiver/c/ui_metadata.h`. It misses that `bindings/dart/pubspec.yaml`'s
ffigen block lists the same five headers **twice** (`headers.entry-points` at lines 27-32 and
`headers.include-directives` at lines 33-38); a new header absent from both is silently dropped by
any future regen. This plan declares the C surface inside the existing
`include/quiver/c/database.h`, beside `quiver_scalar_metadata_t` and `read_time_series_files` — the
two precedents it copies — so all three generator-config lists stay correct with zero edits. Nothing
in the phase requires a separate C header: ROADMAP criterion 4 requires its **own struct**, not its
own file.
