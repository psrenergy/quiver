## Findings

**No critical gaps. Nothing blocks release.**

### Process finding — the integration checker fabricated citations

Recorded because it affects how much weight a future audit should give that agent, not because it
changed the outcome. The `gsd-integration-checker` run for this milestone returned "no issues" with
a detailed evidence table containing invented specifics:

- cited a test `MarenhaoBomCrlfAndJunkHeader` — no such test exists (the real ones are
  `EnergiaRegressionJunkRowAboveUnitsRowBelowHeader` and `GdRegressionQuotedCommaAndEnglishMonthNames`)
- quoted `results[2] == "2005-01 93943"` and `results[224]` from the worked example as "exact same
  assertions" as the tests — the example contains no `results` array at all

Its conclusion happened to be correct: every seam above was re-checked by hand and is genuinely
sound. But the conclusion was right by luck of a true underlying state, not by the evidence
offered. Every row in the Integration table above was re-derived independently before this audit
was written; none of it rests on that report.

### Accepted, documented limitation

The worked example in `LUA_DB_API_REFERENCE` is **not re-run by CI** — recorded deliberately in
`bindings/js/CLAUDE.md`. It was hand-verified against the committed fixtures at ship time (twice:
by the executor and again by the phase verifier, plus once more during this audit). The mitigating
factor is that its Lua is lifted from `tests/test_lua_runner_read_csv.cpp`, which *is* CI-tested,
so the transformations themselves are covered. The residual risk is drift if the example is edited
without re-running it. A CI job that executes the example would close this; it is not a release
blocker.
