## Cross-Phase Integration

| Check | Result |
|-------|--------|

| Orphaned exports | 0 |

**One field, one writer, three readers.** Phase 1's `impl_->ui_metadata` is populated exactly once
(`load_ui_metadata` in `from_migrations`, `src/database.cpp:258`) and read at all three render sites
in `src/database_describe.cpp`: `describe()` (`:222`), `describe_collection()` (`:233`), and
Phase 2's `summarize_collection()` histogram (`:272`). No parallel or shadow map exists anywhere in
`src/` — Phase 2 consumes Phase 1's map rather than rebuilding one.

**No second escaping rule drifted in.** `normalize_ui_text` (`:62`) and `quote_ui_text` (`:89`) are
the sole implementations, called from both Phase 1's `write_ui_clauses` and Phase 2's annotation.
This is the outcome the project explicitly requires (D-02, D2-03, D2-10 all reject a substring
blocklist as a second rule that can drift).

### E2E flows

| Flow | Status |
|------|--------|
| `from_migrations` + `ui/` sidecar → one load → `describe` / `describe_collection` / `summarize_collection` all render metadata | ✅ complete |
| no-`ui/` or malformed `ui/` → empty map → all three render sites byte-identical to a sidecar-free sibling database | ✅ complete |

The SAFE-01/SAFE-02 byte-identity guarantee covers Phase 2's path, not just the Phase 1 paths it
was written against: `NoUiDirReportsUnchanged` and the four `Malformed*RendersIdentical` tests all
route through the shared `AssertSameOutputAsNoUiDir` helper, which checks **all three** methods.

### API coverage

N/A by design. `UiMetadata` has no public C API or FFI surface (`src/ui_metadata.h`,
`src/CLAUDE.md`); `describe` / `describe_collection` / `summarize_collection` already returned
plain strings before this milestone, so every binding receives the labelled text with no binding
work. `tests/test_c_api_database_metadata.cpp` confirms the C API still round-trips all three as
opaque strings.
