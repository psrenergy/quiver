  <action>
Add three tests to the `LuaRunner_ReadCsv` suite covering PARSE-02 through PARSE-07.

Build the composite fixture with `write_lua_csv_file` using the exact content recorded in
02-CONTEXT.md, spelled as explicit escapes in the C++ string literal so the bytes are unambiguous:
the three BOM bytes, then a three-name header, then a row whose first field is a quoted string
containing a comma, a row whose first field is a quoted string containing a doubled quote, a row
whose first field is a quoted string containing a newline, and a final row with only one field.
Line endings are carriage-return-plus-newline throughout. Expect exactly the output 02-CONTEXT.md
records: a clean three-name header, the quoted comma as one field, the doubled quote unescaped to
one quote, the embedded newline preserved inside a single field without splitting the record, and
the short final row present with one field and nothing beyond it.

Test 3 exists because PARSE-05 interacts with plan 02-01's new option: research confirmed
empirically that csv-parser strips the BOM once on the raw byte stream, before and independently of
any header-row resolution, so it holds for an explicit header row and for no-header mode alike.
That is a property worth pinning now that both modes are reachable, and it costs one fixture.

Reuse the existing `RaggedRowsSurviveShort` for PARSE-07 under the default header mode; the
composite fixture covers the ragged case a second time to prove it survives alongside the quoting
cases rather than only in isolation.

Name each assertion's requirement in a trailing comment on the assert line so the coverage is
auditable without re-deriving it from the fixture.
