<objective>
Wire `vincentlaucsb/csv-parser` 5.3.0 into the C++ core behind a new internal reader and put both
Lua entry points on it, so a script running against a file-backed database can read a CSV off disk
whole-file or row-by-row, sandboxed exactly like every other file-touching Lua operation.

Purpose: the agent that drives `LuaRunner` today transcribes CSV contents into script literals by
hand because `io` is deliberately absent from the Lua sandbox. This plan is the end-to-end path that
replaces that.
Output: `src/csv_read.h` + `src/csv_read.cpp` (new internal TU, no public header), `db:read_csv` and
`db:read_csv_stream` registered in `src/lua_runner.cpp`, their `LUA_DB_API_REFERENCE` entries, and a
new `LuaRunner_ReadCsv` gtest suite.
</objective>

**Dependency (D-11).** In `cmake/Dependencies.cmake`, directly after the `rapidcsv` block, declare
`csv_parser` from `https://github.com/vincentlaucsb/csv-parser.git` at `GIT_TAG 5.3.0`. Before
`FetchContent_MakeAvailable`, FORCE all four cache variables: `CSV_ENABLE_THREADS` OFF,
`CSV_NO_SIMD` ON, `CSV_BUILD_PROGRAMS` OFF, `CSV_BUILD_TESTS` OFF — the upstream defaults are ON,
OFF, ON, ON respectively. After `MakeAvailable`, set `EXCLUDE_FROM_ALL YES` on the `csv_no_simd`
target: it duplicates all nine of `csv`'s sources, nothing links it, and csv-parser declares no
install or export rules for it, so excluding it is safe here — the neighbouring lua-cmake warning
about EXCLUDE_FROM_ALL does not transfer, and the new block needs a comment saying so. Add a second
comment on the `CSV_NO_SIMD` line recording why it can never be turned back on: with SIMD enabled
csv-parser adds `/arch:AVX2` as a PUBLIC compile option, which propagates into `quiver` itself and
would SIGILL on pre-AVX2 x86 for every shipped PyPI wheel, npm native, Julia artifact and S3 binary.
Do not attempt `single_include/csv.hpp` — at 5.3.0 it is an `#error` stub.

In `src/CMakeLists.txt`, add `csv_read.cpp` to `QUIVER_SOURCES` after `database_csv_import.cpp`, and
add `csv` to the PRIVATE link list after `rapidcsv`. It stays PRIVATE: public headers in this repo
carry zero third-party includes and `cmake/Platform.cmake` sets hidden visibility.

**Core reader (D-09, D-10, D-12, D-03, D-04, D-20, D-21).** Create `src/csv_read.h` declaring a
`quiver::csv_read` namespace with: a plain `Options` struct carrying `char separator = ','`; a
`RowSink` alias for a callable taking the moved-from row cells plus the 1-based `int64_t` data-row
index and returning `bool` (`false` stops the read); and a `Reader` class. `Reader`'s constructor
takes the resolved absolute path, the caller's own spelling of the path, the operation name, and
`Options`; it exposes `header()` returning the raw column names and `for_each_row(sink)` returning
the `int64_t` count of rows fed to the sink. `Reader` uses Pimpl with a `std::unique_ptr` — that is
load-bearing, not style: `lua_runner.cpp` includes this header, and csv-parser's headers must stay
out of that translation unit, which already needs `/bigobj` on MSVC for sol2's template depth.
There is no public `include/quiver/` counterpart, no `QUIVER_API`, no C API and no FFI binding: this
is the first internal `.cpp` in `src/` with no public header, which is a deliberate new pattern.

`src/csv_read.cpp` is the only file that includes a csv-parser header, and it includes
`<internal/csv_reader.hpp>` rather than the umbrella header, which also drags in the DataFrame and
the writer. Build the `csv::CSVFormat` in exactly one place — `Reader`'s constructor — pinning
three things and only three: `delimiter` from `Options::separator`; `variable_columns` to
`csv::VariableColumnPolicy::KEEP_NON_EMPTY` (the library default `IGNORE_ROW` silently discards any
row whose field count differs from the header, which would violate D-02 and PARSE-07); and
`header_row(0)` (with no explicit header row the library infers one and pops every record up to the
guessed index, silently eating a title line above the real header — the exact shape of the files
this milestone exists for). Never call `guess_csv()`; leave `trim_chars` and eager field
classification at their defaults, which is what preserves header spacing and keeps type inference
off. Write no `chunk_size` call at all (D-18): with threads compiled out the read window is the
library's own fixed default, unmultiplied by worker count, which is precisely what PARSE-09 requires
— add a comment saying that if `CSV_ENABLE_THREADS` is ever turned back on, `format.threading(false)`
has to be added here.

Validation order inside the constructor, all Pattern 1 and all quoting the caller's own spelling of
the path rather than the resolved absolute one (D-21): file does not exist →
`Cannot <op>: file not found: <p>`; path is a directory → `Cannot <op>: path is a directory: <p>`;
file is zero-length → `Cannot <op>: file '<p>' is empty` (D-03 — this check belongs here, in the
shared code, so the two entry points cannot disagree on an empty file). `<op>` is the operation name
threaded in from the caller exactly the way `resolve_sandboxed_path` already threads its own.
Wrap the `csv::CSVReader` construction and the iteration in try/catch and translate any csv-parser
exception into `Cannot <op>: cannot read file '<p>': <reason>` — no csv-parser or standard-library
message may reach Lua unwrapped (LUA-08).

In `for_each_row`, copy each field into an owned `std::string` inside the loop via
`field.get<std::string_view>()` and let the `csv::CSVRow` die every iteration. Retaining a `CSVRow`
pins the reader's whole mapped chunk through a shared pointer and silently defeats the bounded
window. Stop the loop the moment the sink returns `false` and return the count of rows actually fed.

**Lua binding (D-01, D-02, LUA-04).** Register `read_csv` as a plain `bind.set_function` entry in
the sandboxed file-op block immediately after `csv_to_bin`. That region carries no NOLINT pairs —
the three in the file wrap only the `new_usertype` and namespace blocks — so do not add a fourth.
The lambda takes `Database& self` and the path, calls
`resolve_sandboxed_path(self, "read_csv", path)` first, constructs a `csv_read::Reader` with default
`Options`, and returns one Lua table with two keys: `header`, set from `to_lua_table` over
`Reader::header()` and set only when that vector is non-empty (D-01 requires the key to be absent
rather than an empty table when a file has no header — Plan 02 and Phase 2 depend on that meaning
exactly one thing); and `rows`, set from the nested `to_lua_table` overload over the collected
`std::vector<std::vector<std::string>>`. Collect by passing a sink that always returns `true`.
Return one table, never two values: `LuaRunner::run` encodes only the first returned value, so a
second return is silently dropped. Do not write a new marshaling helper — `to_lua_table` is
documented as the only vector→table marshaler in this codebase.

**Agent reference (DOC-01).** In `bindings/js/src/lua-api.ts`, add `db:read_csv` to the
parenthetical list in the filesystem-sandbox bullet, and add a `db:read_csv` entry in the same
compact style as the existing `db:bin_to_csv` / `db:csv_to_bin` entries. The entry must state the
signature, the `{header = ..., rows = ...}` shape with positional row addressing, that every cell
is a string with no numeric or date inference so a zero-padded code keeps its zeros, that a 0-byte
file throws, and that a header-only file yields an empty `rows`. Both the sandbox-bullet token and
the entry must spell the name as the literal `db:read_csv` — `lua-api-sync.test.ts` scrapes
`bind.set_function` names out of `lua_runner.cpp` and fails the JS suite the moment a name exists
without a matching literal token here, which is why this edit ships in this task and not later.

branch of the encoder and the whole host contract in a single assertion.

Build the header Lua table **once, before the loop**, from `Reader::header()`, and pass it by value
into each callback invocation. Reaching the header during the stream is not a convenience: without
it a model writes the universal streaming idiom that treats the first row as the header, which
silently consumes the first data record and turns every column name into a cell value — producing a
downstream error that names a cell value and points at neither this function nor the header, or on a
numeric-first-column file no error at all and one row short.

Invoke the callback as `fn(row_table, index, header_table)` where `index` is the 1-based ordinal of
the **data** row (the header row is not counted) and `row_table` is the same 1-based array of
strings `db:read_csv` puts in `rows`, never padded to header width. Lua discards extra arguments, so
`function(row)` and `function(row, i)` keep working — the arity is opt-in.

After every invocation, check `result.valid()`; on failure extract `sol::error err = result;` and
`throw std::runtime_error(err.what())` so the Lua error propagates verbatim and unwrapped. Do not
add manual cleanup: the reader is a stack local and sol2's trampoline catches the exception before
calling into Lua, so normal C++ unwinding closes the file.

Early stop (D-06): read the callback's return with `sol::optional<bool>` and stop only when it
compares equal to `false` — `if (result.return_count() > 0 && result.get<sol::optional<bool>>(0) == false)`.
`sol::optional<bool>` is a strict type check that short-circuits past the safety-getter macro and is
therefore identical in Debug and Release. Do not use `get<bool>`: that is truthiness and would read
a callback that returned nothing at all as a stop signal. A callback whose last statement is an `if`
that did not fire returns nothing, and returning nothing must mean continue.

Return the number of data rows fed to the callback as `int64_t` — house counts are `int64_t`, not
`size_t`. Under an early stop this is a partial count.

fails silently rather than loudly: that `index` is 1 on the first **data** row, so skipping index 1
to skip a header drops a real record; that the returned number counts rows *read*, not rows the
callback *kept*, so a filtering callback logging it as "imported N" is wrong; and that `return false`
stops the read, so a callback whose last statement is a comparison truncates the stream. Both
occurrences must spell the literal token `db:read_csv_stream` or the JS suite fails.

truncating the stream (the documented hazard, pinned so it stays deliberate); a callback that raises
